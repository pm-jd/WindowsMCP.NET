# Expect Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only MCP tool `Expect` that evaluates a list of conditions against a fresh observation with fixed rules and returns `pass` / `fail` / `unknown` per condition, optionally waiting until all hold.

**Architecture:** Three pure units (parser, evaluator, formatter) over the existing `Observation` model, plus a thin tool with an injectable wait loop. Nothing in the collection or action path changes except one copied flag (`ObservedElement.Password`).

**Tech Stack:** net10.0-windows, ModelContextProtocol SDK 2.2.0, xunit v3 on Microsoft.Testing.Platform, System.Text.Json.

**Spec:** `docs/superpowers/specs/2026-10-04-expect-design.md` — read it first; the table in §1.2 is the contract.

## Global Constraints

- An answer is `pass` or `fail` only when the observation proves it; everything else is `unknown` with a reason. When in doubt, `unknown`.
- `Expect` sends no input to the UI. `ReadOnly = true`, `Idempotent = true`.
- `fail` / `unknown` are not tool errors (`IsError` stays false). `[ERROR]` only for invalid input, missing `process`, cancellation, or an observation that throws.
- Limits: 1–20 conditions; `timeout_ms` clamped 0–30000; poll pause 200 ms; observation taken with `max_elements = 500`.
- Names, panels, window titles: `StringComparison.OrdinalIgnoreCase`. Values: `StringComparison.Ordinal`. `text`: contains, `OrdinalIgnoreCase`.
- Condition indexes are 1-based in every message and output.
- Follow the repo conventions: tool body in try/catch → `ToolHelpers.ErrorResult`; enums in `Tools/ToolEnums.cs` carry `[JsonConverter(typeof(SnakeCaseEnumConverter<T>))]`; CRLF line endings; comment density like the neighbouring files.
- Build: `dotnet build src/WindowsMCP.NET -c Release` (0 warnings). Tests: `dotnet test tests/WindowsMCP.NET.Tests -c Release -v q`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.

## Review Focus

1. **A selector that matches an element twice through `name` and `label`** (name `Focus`, label `Focus`) must count as one match, not "several".
2. **A condition with an `element` id that is not in the observation while the list is complete** → `fail` ("no element with id …"), not an exception.
3. **A JSON condition whose `state` is not a string, or whose `window` is a number** → `[ERROR]` naming the index, not an `InvalidOperationException` from `GetString`.
4. **Empty title match:** `{"window": ""}` with `match=contains` would match every window → rejected by the parser (empty `window`, `name`, `text`, `element` are invalid).
5. **Timeout shorter than one observation** (`timeout_ms = 1`): exactly one observation, result returned, `timed_out = true` only when the result is not `pass`.

Each line has its test in the owning task below.

public enum ExpectState { Exists, Absent, Enabled, Disabled, Selected, NotSelected, Checked, Unchecked, Expanded, Collapsed }

public enum ExpectMatch { Exact, Contains }
public enum ExpectResult { Pass, Fail, Unknown }

// Models/Expectation.cs
public abstract record Expectation(int Index);
public sealed record WindowExpectation(int Index, string Title, ExpectWindowState State, bool? Modal, ExpectMatch Match) : Expectation(Index);
public sealed record ElementExpectation(int Index, string? Id, string? Type, string? Name, string? Panel, string? InWindow,
    ExpectState State, string? Value, string? ValueContains, ExpectMatch Match) : Expectation(Index);
public sealed record TextExpectation(int Index, string Text) : Expectation(Index);
public sealed record ConditionOutcome(int Index, ExpectResult Result, string Condition, string Actual, IReadOnlyList<string> ElementIds);
public sealed record ExpectOutcome(ExpectResult Result, IReadOnlyList<ConditionOutcome> Conditions, int Observations, long ElapsedMs, bool TimedOut);

// Services/ExpectationParser.cs
public static class ExpectationParser
{
    public const int MaxConditions = 20;
    /// <exception cref="ArgumentException">message starts with "condition N: " (or "conditions: " for the list itself)</exception>
    public static IReadOnlyList<Expectation> Parse(JsonElement conditions);
}
```

Parser rules (spec §1.1): kind by key — `window` → window; `text` → text; `element` or `type`/`name` → element. Allowed keys per kind: window `window,state,modal,match`; element `element,type,name,panel,in_window,state,value,value_contains,match`; text `text`. Any other key, two kinds, or no kind is an error. `element` (id) excludes `type,name,panel,in_window,match`. `value` and `value_contains` exclude each other and `state=absent`. `modal` only with `state=open`. String fields must be JSON strings and non-empty (except `value`, which may be `""`); `modal` must be a JSON boolean. Enum values are read through the enum converter; an unknown value's message lists the allowed ones in snake_case.

public bool Password { get; init; }

public static class ExpectationEvaluator
{
    public static IReadOnlyList<ConditionOutcome> Evaluate(Observation observation, IReadOnlyList<Expectation> expectations);
    public static ExpectResult Overall(IReadOnlyList<ConditionOutcome> outcomes); // all pass → Pass; any fail → Fail; else Unknown
    /// <summary>The condition as one line, e.g. "window 'Login' open, modal", "Button 'OK' enabled", "element ejsbw value 'x'", "text 'finished'".</summary>
    public static string Describe(Expectation expectation);
}
```

Facts the evaluator relies on (verify in `ObservationService`/`ObservationBuilder` before coding):
- `ObservedElement.Toggle` is `ToggleState.ToString()`: `"On"`, `"Off"`, `"Indeterminate"`, or null. `Expand` is `ExpandCollapseState.ToString()`: `"Expanded"`, `"Collapsed"`, `"PartiallyExpanded"`, `"LeafNode"`, or null. `expanded` passes on `"Expanded"`, `collapsed` on `"Collapsed"`; the opposite fails; anything else is `unknown`.
- `ObservedElement.Window` is the title of the element's window, null for the main window = `observation.Windows[^1]`.
- "List is cut" = `observation.Omitted > 0 || observation.Truncated`.
- A missing value (`Value == null`) on a non-password element is the empty string.
- Selector: `Type` equals `e.Type` (OrdinalIgnoreCase); `Name` matches `e.Name` **or** `e.Label`; `Panel` matches `e.Panel`; `InWindow` matches the element's window title. An element is counted once.
- `Actual` wording is free but must contain: the found state (`enabled`/`disabled`, `value is '…'` clipped with `ObservationFormatter` limits, `selected`/`not selected`, toggle/expand state), or the reason for `unknown`: `the element list is cut (N more) — absence cannot be proven`, `N elements match — narrow the selector`, `a TabItem does not report its selection reliably`, `a password field's value is never collected`, `reports no toggle state`, `reports no expand state`, `a window in scope is unreadable`. `ElementIds`: ids of the matches, at most five.

```csharp
[McpServerToolType]
public static class ExpectTools
{
    public const int MaxTimeoutMs = 30_000;
    public const int PollPauseMs = 200;
    public const int ObserveMaxElements = 500;

    [McpServerTool(Name = "Expect", ReadOnly = true, Idempotent = true)]
    public static async Task<CallToolResult> Expect(ObservationService observation, ObservationStore store,
        JsonElement conditions, int timeout_ms = 0, ObserveScope scope = ObserveScope.Foreground, string? process = null,
        OutputFormat format = OutputFormat.Markdown, CancellationToken ct = default);

    /// <summary>The wait loop (spec §1.3), free of UIA and real time.</summary>
    internal static async Task<ExpectOutcome> RunAsync(IReadOnlyList<Expectation> expectations, Func<Observation> observe,
        Action<Observation> remember, int timeoutMs, TimeProvider time, Func<TimeSpan, CancellationToken, Task> pause, CancellationToken ct);
}
```

Loop: observe → `remember` → evaluate → if overall `Pass`, or the elapsed time (from `time.GetTimestamp()`) plus `PollPauseMs` would reach `timeoutMs`, return; else `pause(200 ms)` and repeat. `TimedOut` = `timeoutMs > 0` and the result is not `Pass`. `ct.ThrowIfCancellationRequested()` before each observation. The tool passes `TimeProvider.System` and `Task.Delay`. The tool description states: what it is for, the three condition kinds with one example each, the states, `match`, the meaning of `unknown`, that fail/unknown are not errors, and the JSON shape (same style as the `Observe` description).
